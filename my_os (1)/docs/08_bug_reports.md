# Отчёты о дефектах (Bug Reports) — ИС «StudyOS»

В данном документе зафиксированы все 5 дефектов, обнаруженных в процессе интеграции модулей и проведения системных сценариев тестирования, а также статусы и методы их устранения.

## Дефект №1. Циклическое удаление каталогов (Критический)
- Идентификатор: BUG-001
- Компонент: fs.py / syscalls.py
- Описание: При вызове команды rmdir для непустого каталога система удаляла только саму запись каталога из базы данных, оставляя дочерние файлы и папки «сиротами» (с некорректными parent_id). Это приводило к нарушению целостности базы данных и невозможности построения дерева tree.
- Ожидаемый результат: Ошибка о наличии вложенных элементов или их корректное каскадное/рекурсивное удаление.
- Фактический результат: Каталог удаляется, вложенные объекты остаются в БД без родителя.
- Статус: Исправлено.
- Решение: В fs.py добавлена рекурсивная функция для очистки всех дочерних элементов перед удалением целевой директории.

## Дефект №2. Обход проверки прав доступа (Блокирующий)
- Идентификатор: BUG-002
- Компонент: shell.py / auth.py
- Описание: Логика проверки роли текущего пользователя (Admin/User) изначально находилась внутри shell.py. Если вызывать методы напрямую через API ядра или сторонний скрипт в обход оболочки, проверка прав не выполнялась, и обычный пользователь мог выполнять административные команды.
- Ожидаемый результат: Любой вызов привилегированной команды должен блокироваться на уровне ядра ОС.
- Фактический результат: Ограничения проверяются только при вводе команды в CLI shell.
- Статус: Исправлено.
- Решение: Логика авторизации и валидации сессий полностью перенесена из shell.py в модуль syscalls.py, который служит единой точкой входа для ядра.

## Дефект №3. Поверхностное копирование директорий (Критический)
- Идентификатор: BUG-003
- Компонент: fs.py
- Описание: При выполнении команды copy для папки создавался новый каталог с тем же именем, но всё его внутреннее содержимое (вложенные файлы и подкаталоги) не дублировалось в новое место.
- Ожидаемый результат: Полное дублирование структуры папки со всеми вложенными объектами.
- Фактический результат: Создается пустой каталог-клон.
- Статус: Исправлено.
- Решение: Реализован алгоритм глубокого рекурсивного обхода дерева файлов с повторным вызовом touch/mkdir для каждого вложенного элемента.

## Дефект №4. Падение системы при превышении лимита памяти (Высокий)
- Идентификатор: BUG-004
- Компонент: scheduler.py / memory_state
- Описание: Во время стресс-тестирования при запуске процесса (run) в условиях, когда доступные страницы памяти исчерпаны, происходило аварийное завершение работы всего скрипта Python (Crash) вместо штатной обработки ошибки.
- Ожидаемый результат: Команда run должна вернуть ошибку «Недостаточно памяти» со статусом DENIED/ERROR и продолжить работу оболочки.
- Фактический результат: Необработанное исключение валит весь процесс ОС.
- Статус: Исправлено.
- Решение: В scheduler.py добавлен блок try/except, перехватывающий исключения подсистемы памяти, и возвращающий корректный код ошибки ядру.

## Дефект №5. Смещение форматирования дерева tree (Низкий)
- Идентификатор: BUG-005
- Компонент: shell.py (отображение)
- Описание: При вызове команды tree в условиях сверхглубокой вложенности каталогов (более 8 уровней) символы псевдографики (├──, └──) смещаются, из-за чего нарушается визуальное восприятие иерархии в консоли.
- Ожидаемый результат: Ровные отступы на любом уровне вложенности.
- Фактический результат: Начиная с 8 уровня линии начинают «съезжать» вправо на лишний пробел.
- Статус: Отложено с обоснованием.
- Обоснование: Данный дефект носит исключительно косметический характер, не влияет на логику работы файловой системы и стабильность интеграции модулей. Исправление перенесено на следующий этап разработки (рефакторинг CLI).
