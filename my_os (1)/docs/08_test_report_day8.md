## 2. Результаты выполнения системных сценариев

### Сценарий №1: Регистрация и разграничение прав доступа
- Шаги: Регистрация пользователя `user1` -> Попытка вызова `rmdir /bin` -> Попытка просмотра `logs`.
- Результат: Модуль `auth.py` совместно с `syscalls.py` успешно перехватили вызовы. Действия заблокированы.
- Статус: Успешно (PASSED)

### Сценарий №2: Иерархические операции над файлами
- Шаги: Создание структуры каталогов -> Рекурсивное копирование `copy` папки с вложенными файлами -> Вызов `tree`.
- Результат: В таблице `files` СУБД SQLite связи `parent_id` созданы корректно. Дерево выводится без искажений.
- Статус: Успешно (PASSED)

### Сценарий №3: Жизненный цикл процесса и логирование памяти
- Шаги: Инициализация ядра -> Вызов `run` для симуляции процесса -> Проверка ОЗУ командой `mem` -> Завершение через `kill`.
- Результат: Модули `scheduler.py` и `kernel.py` отработали штатно. Страницы памяти выделены и полностью освобождены после завершения.
- Статус: Успешно (PASSED)

### Сценарий №4: Стресс-тестирование лимитов памяти и сквозной аудит
- Шаги: Непрерывный циклический запуск процессов до исчерпания страниц памяти -> Чтение журнала вызовов через `logs`.
- Результат: После фиксации дефекта BUG-004 система больше не падает. Ядро возвращает ошибку нехватки ресурсов. Все отказы со статусом `DENIED` зафиксированы в таблице `syscalls_log` через `logger.py`.
- Статус: Успешно (PASSED)
