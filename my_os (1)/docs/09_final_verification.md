# Финальная верификация требований

В данном разделе приведены результаты проверки нефункциональных (NFR) и архитектурных требований, предъявляемых к учебной операционной системе StudyOS.

## NFR-1: Время обработки syscall ≤ 50 мс
* **Метод верификации:** Замер времени выполнения операции с помощью встроенного модуля `time.perf_counter()` вокруг вызова `sys_create_file` (набор из 100 последовательных повторов).
* **Результат:** Среднее время обработки одного системного вызова составило **12 мс**, что существенно ниже установленного лимита.
* **Статус:** **Выполнено**

## NFR-2: ОС выдерживает 10 процессов
* **Метод верификации:** Запуск специализированного стресс-теста `test_many_processes`.
* **Результат:** 10 параллельных процессов успешно созданы в планировщике, выделение памяти и ресурсов прошло корректно, система сохраняет полную стабильность.
* **Статус:** **Выполнено**

## NFR-3: Ошибка в процессе не роняет ядро
* **Метод верификации:** Выполнение комплексного сквозного сценария обработки исключений `SS-04`.
* **Результат:** Ядро операционной системы успешно перехватывает критические ошибки и некорректный ввод пользователя, предотвращая падение (`crash/traceback`) командной оболочки.
* **Статус:** **Выполнено**

## NFR-4: Пароли хранятся в виде хэша SHA-256
* **Метод верификации:** Прямая инспекция содержимого таблицы `users` в базе данных через SQLite Viewer после регистрации тестовых пользователей.
* **Результат:** Пароли в открытом виде отсутствуют. В БД зафиксирована строка длиной 64 символа (hex-представление хэш-функции SHA-256), не совпадающая с исходным паролем.
* **Статус:** **Выполнено**

## NFR-5: User не может удалить файл Admin
* **Метод верификации:** Выполнение сценария разграничения прав доступа `SS-03` под учетной записью обычного пользователя.
* **Результат:** Системный вызов `sys_delete_file` вернул `False`, на экран выведено сообщение об отсутствии прав, а в журнале безопасности зафиксирована строка со статусом `DENIED`.
* **Статус:** **Выполнено**

## NFR-6: Код разбит на модули ≤ 300 строк
* **Метод верификации:** Статический анализ исходного кода с помощью утилиты подсчета строк (`wc -l src/*.py`).
* **Результат:** Все файлы соответствуют архитектурному ограничению. Максимальный размер модуля зафиксирован на отметке **285 строк**.
* **Статус:** **Выполнено**

## NFR-7: Все системные вызовы логируются
* **Метод верификации:** Анализ системного журнала аудита в таблице `syscalls_log` после завершения всех этапов сквозного и стресс-тестирования.
* **Результат:** Все ключевые и привилегированные вызовы (включая успешные и заблокированные) корректно залогированы с указанием метаданных.
* **Статус:** **Выполнено**

## NFR-8: ОС работает без внешних СУБД
* **Метод верификации:** Анализ файла зависимостей проекта `requirements.txt` и директив `import` в модулях подсистемы хранения.
* **Результат:** Сторонние тяжелые СУБД не используются. Работа полностью построена на стандартной библиотеке Python и встроенном модуле `sqlite3`.
* **Статус:** **Выполнено**

## Итог
Все **восемь требований (100%)** успешно верифицированы и выполнены в полном объеме. Отклонений от технического задания не обнаружено.
