## Слайд 3. Архитектура системы

- Подзаголовок: Однонаправленная диаграмма компонентов (8 модулей)
- Схема взаимодействия: shell.py $\rightarrow$ syscalls.py $\rightarrow$ kernel.py $\rightarrow$ Подсистемы (auth.py, fs.py, scheduler.py, logger.py) $\rightarrow$ db.py
- Краткое описание связей:
- Интерфейс пользователя (shell) взаимодействует с ядром исключительно через системные вызовы (syscalls).
- kernel координирует состояние системы и распределяет задачи по подсистемам.
- Подсистемы используют db для сохранения и извлечения данных из СУБД SQLite.

## Слайд 4. Иерархическая файловая система

- Структура БД (Таблица files):
- id (INT, Primary Key) — уникальный идентификатор файла/папки.
- name (TEXT) — имя объекта.
- is_dir (BOOLEAN) — флаг (каталог или файл).
- parent_id (INT, Foreign Key к files.id) — ссылка на родительский каталог.
- Реализация иерархии: Поле parent_id обеспечивает неограниченную древовидную вложенность.
- Пример дерева каталогов (команда tree):

/ (root)
├── bin/
├── home/
│   └── user1/
│       └── document.txt
└── var/log/

## Слайд 6. Разграничение прав доступа

- Ролевая модель: Реализовано жесткое разделение прав между ролями Admin (полный доступ) и User (ограниченный доступ).
- Пример сценария проверки прав:
- Пользователь user1 пытается удалить системный каталог: rmdir /bin
- Модуль auth.py перехватывает вызов, проверяет привилегии текущей сессии и генерирует отказ в доступе.
- Вывод в консоль: Error: Access denied. Administrator privileges required.
